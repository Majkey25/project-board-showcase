Project board

Projects by phase. Versions by environment.

A private board where each project is one card moving through your own workflow, while its target, test and production versions stay in view. Connected to GitHub, with status updates, automations, custom notifications, a GitHub audit and a scoped API for AI agents.

01 · Board

Your workflow, your columns

Columns follow the way your team works. Each maps to one of ten stages, such as planning, review, fixes, retest or production, so the board knows what each column means.

  • Drag and drop with the pointer, or move and reorder from the keyboard
  • Search, and filter by person, tier, priority or blocked state
  • Order by hand or by priority; work-in-progress limits warn without blocking
  • Each person picks which details cards show: next step, dates, GitHub, fields
Full size
02 · Update status New

State changes, apart from editing

What changes every day has its own tab: column, next step, priority, blocking, assignee, due date and versions. Name and description stay in Edit, so a quick update never overwrites them.

  • Suggestions from open pull requests, such as “Get #128 reviewed and merged”
  • Moving a card runs the column’s automation first; your own values win
  • Only the fields you changed are saved; a concurrent change is caught, not overwritten
  • Quick actions sit right below for one-click transitions
Full size
03 · Overview

The state of a project at a glance

Opening a project shows what matters first: where it is, what happens next, who owns it and when it is due, then what is open against it on GitHub.

  • Next step highlighted; overdue dates flagged here and on the card
  • Target, test and production versions side by side
  • Checklist progress at a glance
  • Open pull requests, drafts and issues, each linking straight to GitHub
Full size
04 · Editing

What you set once, in one form

Name, summary, description, checklist, custom fields, tier and rating. Unsaved changes survive switching tabs, and two people editing at once never overwrite each other silently.

  • Every save carries a revision; a stale one is refused and your draft is kept
  • Checklists of up to 50 items
  • Archive and restore instead of losing work; deleting needs the name typed
  • Board-wide notes and a full change history for every project
Full size
05 · GitHub

Pull requests, issues and branches, per person

Link up to five repositories to a project and see what is open against them. Every visitor sees only what their own GitHub account can see, and nobody learns that a hidden repository exists.

  • Open and draft pull requests, issues with labels, branches with protection
  • Link individual issues and pull requests to projects
  • Counts of pull requests, drafts and issues on every card
  • An optional personal token, with a check of how many of your linked repositories it opens
Full size
06 · Automations

Quick actions that run by themselves

A quick action applies several changes at once. An automation runs one whenever a project enters a chosen column, so “Fixes and retest” can raise the priority and set the next step without anyone remembering to.

  • Move, prioritise, tier, rate, block, archive or set the next step
  • Up to 12 quick actions; one automation per column
  • Runs in the same write as the move and is recorded in history
  • Rules never chain, so nothing loops
Full size
07 · Notifications

Hear about exactly what you care about

All changes, finished projects only, or your own pick of twelve events, optionally only for the projects assigned to you.

  • Added, edited, moved, done, blocked, unblocked
  • Assigned to you, taken off you, due date changed
  • Archived, restored, deleted
  • Browser notifications that never show project details
Full size
08 · Project Guard

Audit your GitHub work against your rules

Guard reads the issues and pull requests you can access and reports the ones missing what you require: an assignee, a GitHub Project, a project field, a linked branch. It changes nothing on its own, and every option explains itself.

  • Scope by owner, repositories, states, dates and assignees
  • Rules for assignees, GitHub Project membership, required fields and development links
  • Prepares changes as a preview you approve; previews expire after 15 minutes
  • Personal results, never shared; export to CSV or Excel
Full size
09 · AI agents

A safe door for agents and scripts

Scoped, expiring tokens let an agent read or update one board, never with more rights than the person who created it. The board describes itself in a format language models read well.

  • Six scopes, read-only by default; write, propose and merge are opt-in
  • Tokens expire within 90 days and are stored only as hashes
  • OpenAPI 3.1, llms.txt and a board context with project summaries
  • Every agent change is recorded; revoking is immediate
Full size
10 · AI assistance

Ask about your board with your own model

Connect your own OpenAI or Azure OpenAI account. You choose what context is sent; nothing leaves just because a board was opened.

  • Keys encrypted on the server, never returned to the browser
  • Tasks such as suggesting a priority or assessing severity
  • Suggestions stay proposals until you apply them
  • Local models through a small companion for Ollama
Full size
11 · Sharing

Roles that make sense

Owner, administrator, editor and viewer. Administrators can do everything except delete the board or change who owns it.

  • Invite by GitHub username, even before the person has signed in
  • Invitation links with a role, expiry, use limit and revocation
  • Removing someone cuts off their access immediately
  • Ownership transfer when a board changes hands
Full size
12 · Customization

Shape the board to your process

Columns, stages, colours and limits; custom fields of five kinds; tiers and a rating scale. Each person also sets density, font, size, corner radius and column width.

  • Text, number, date, choice and checkbox fields, shown on cards if you like
  • Up to 16 fields; retired ones are archived, never silently deleted
  • Tiers with colours and a rating out of 5, 10 or 100
  • Hints on every control, in English and Czech

Themes

Seven themes, each in light and dark

Established design languages rather than one-off styling: a calm original, a monochrome minimal, Material Design 3, soft gradients, a deep midnight, a terminal matrix, or your own colours. Every palette keeps text at 4.5:1 contrast or better, and the choice follows you to every device.

Security

Built carefully

  • React 19, strict TypeScript and Material Design 3 on the front; a Cloudflare Worker with D1 behind it.
  • Board content encrypted at rest with AES-256-GCM, keys kept outside the database.
  • GitHub tokens encrypted and never returned to the browser; every GitHub read uses the visitor’s own access.
  • Strict Content Security Policy, HSTS, same-origin checks, rate limits and database-level write guards.
  • Every change passes secret scanning, lint, type checks, backend and browser tests, backup checks and a dependency audit.
