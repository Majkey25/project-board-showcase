Everything a project needs, in one card

Each part of the product, in the order you meet it.

01 — Board

Your workflow, your columns

Columns follow the way your team works, and each one is mapped to a stage such as planning, development, testing, production or done.

  • Drag and drop, or move cards from the keyboard
  • Search and filter by person, priority, tier or blocked state
  • Order by hand or by priority; blocked work stands out
02 — Overview

The state of a project at a glance

Opening a project shows what matters first: where it is, what happens next, who owns it and when it is due.

  • Next step, priority, owner, due date with an overdue flag
  • Target, test and production versions side by side
  • Checklist progress and a full change history
03 — Editing

Everything about a project, in one form

Summary, description, versions, checklist, custom fields, tiers and ratings, with unsaved changes kept while you switch tabs.

  • Conflict-safe saving when two people edit at once
  • Archive and restore instead of losing work
  • Notes for the whole board, separate from private data
04 — GitHub

Pull requests, issues and branches, per person

Link repositories to a project and see what is open against it. Every visitor sees only what their own GitHub account can see.

  • Open and draft pull requests, issues, labels and activity
  • Branches with their protection status
  • Counts on each card; issues and PRs can be linked to projects
05 — Automations

Quick actions that run by themselves

A quick action applies several changes at once. An automation runs one whenever a project enters a chosen column.

  • Move, set priority, tier, rating, blocking or archive in one step
  • Runs in the same write as the move, with history
  • Rules never chain, so nothing loops
06 — Notifications

Hear about exactly what you care about

Choose between all changes, finished projects, or a custom set of events — optionally only for projects assigned to you.

  • Added, edited, moved, done, blocked, unblocked
  • Assigned to you, taken off you, due date changed
  • Archived, restored, deleted; browser alerts hide details
07 — Project Guard

Audit your GitHub work against your rules

Guard reads the issues and pull requests you can access and reports the ones missing what you require: an owner, a project, an estimate.

  • Scans repositories and GitHub Projects with your own access
  • Prepares changes you review before anything is applied
  • Personal: results and proposals are never shared
08 — Agent access

A safe door for AI agents and scripts

Create scoped, expiring API tokens so an agent can read or update one board — never with more rights than the person who created it.

  • Read-only by default; write, propose and merge are opt-in
  • Documented API with machine-readable context
  • Every agent change is recorded; revocation is immediate
09 — AI assistance

Ask about your board with your own model

Connect your own OpenAI or Azure OpenAI account. You choose the context; nothing is sent just by opening a board.

  • Keys encrypted on the server, never returned to the browser
  • Suggestions stay proposals until you apply them
  • Local models through the companion for Ollama
10 — Sharing

Roles that make sense

Owner, administrator, editor and viewer. Administrators can do everything except delete the board or change who owns it.

  • Invite by GitHub username or with a link
  • Links with expiry, use limits and revocation
  • Ownership transfer when a project changes hands
11 — Yours

Preferences that follow you

Language, sync interval, themes and hints are saved to your account and apply on every device.

  • Six themes, each in light and dark, plus a custom one
  • Hover hints on every control, in your language
  • Your own GitHub token, used only for your requests

Also included

The details that make it usable every day.

Custom fields, tiers and ratings

Shape projects to your process, shown on cards where you want them.

Export and import

Take a board out as JSON and bring it back, with permission and schema checks.

Automatic sync

Clear terms

All screens show a synthetic demo board.

Built carefully

  • React 19, strict TypeScript and Material Design 3 on the front; a Cloudflare Worker with D1 behind it.
  • Board content encrypted at rest with AES-256-GCM, keys kept outside the database.
  • GitHub tokens encrypted and never returned to the browser; every GitHub read uses the visitor's own access.
  • Strict Content Security Policy, HSTS, same-origin checks, rate limits and database-level write guards.
  • Every change passes secret scanning, lint, type checks, backend and browser tests, backup checks and a dependency audit.
